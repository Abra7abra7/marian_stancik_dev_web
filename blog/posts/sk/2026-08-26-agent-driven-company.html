Problém s „Sólo Founderom"

Keď som začal stavať autonómne AI systémy, mal som jasnú víziu: stavať autonómne AI agenty pre firmy. Bol tu však problém — bol som tím jedného človeka. Každá hodina strávená administratívou bola hodina, ktorú som nestrávil budovaním produktu.

Typická trajektória sólo foundera:

4. Systém Health & Watchdog (3 cron joby)

Watchdog agent kontroluje heartbeat každého iného agenta každých 15 minút. Ak cron job zlyhá, watchdog:

  1. Detekuje anomáliu cez exit kód procesu alebo output delta
  2. Analyzuje koreňovú príčinu (plný disk? API rate limit? chyba v kóde?)
  3. Pokúsi sa o automatické obnovenie s až 3 retry
  4. Ak obnovenie zlyhá, vygeneruje štruktúrovaný report do môjho inboxu

Tento watchdog loop je dôvod, prečo systém udržuje 99,7 % uptime — nie preto, že agenti nikdy nezlyhajú, ale preto, že zlyhania sú zachytené a vyriešené do 15 minút.

Agentná Architektúra: Watchdog Pattern

Najdôležitejší architektonický pattern, ktorý som vyvinul, je watchdog loop. V pseudokóde vyzerá takto:

# Každých 15 minút — watchdog_all.py
for job in all_cron_jobs:
    previous_state = load_checkpoint(job.id)
    current_state = get_current_state(job)

    if previous_state != current_state:
        if state_changed_expected(current_state):
            save_checkpoint(job.id, current_state)
            continue  # Normálna prevádzka
        else:
            alert_level = analyze_anomaly(job, current_state)
            if alert_level >= WARNING:
                attempt_recovery(job)
                notify_owner(job.id, alert_level, diagnosis)

Tento pattern je generický. Môžete ho aplikovať na akýkoľvek autonómny systém — content pipeline, drone operácie, trading boty alebo IoT monitoring. Trik je v tom, že watchdog samotný je monitorovaný vyššou úrovňou agenta (Hermes runtime), čo vytvára self-healing hierarchiu.

Mechanizmy Obnovenia

  • API zlyhania: Exponenciálny backoff (1s, 3s, 9s) s max 3 pokusmi
  • Disk pressure: Automatické čistenie starých logov a checkpointov
  • Pád procesu: systemd auto-restart s 5s oneskorením
  • Memory leak: Memory cap na 80 % celkovej RAM, graceful OOM handling
  • Korupcia stavu: Checkpoint rollback na posledný známy dobrý stav

Ponaučenia

Začni s Jedným Agentom

Najväčšia chyba, ktorú vidím, je že ľudia sa snažia postaviť 10 agentov naraz. Ja som začal s jedným — denný content post — a nechal som ho bežať dva týždne pred pridaním druhého. Každý agent musí preukázať spoľahlivosť, kým dostane súrodenca.

Testuj Obnovenie Skôr Než Funkcionalitu

Keď staviaš autonómneho agenta, testuj čo sa stane keď zlyhá skôr, než testuješ čo robí keď funguje. Pracujúci agent ktorý potichu spadne je horší ako žiadny agent. Watchdog pattern funguje len preto, že som počas vývoja zámerne rozbil každého agenta, aby som overil recovery cesty.

Nechaj Človeka v Slučke — Najskôr

Každý nový agent začína v „supervised mode" — generuje výstup, ale nepublikuje/nevykonáva ho, kým ho neskontrolujem. Keď dôverujem rozhodovacej logike (typicky 2-3 týždne konzistentnej kvality), povýšim ho na plnú autonómiu.

Neostavaj to, čo Môžeš Automatizovať

Toto je meta-lekcia. Predtým než automatizujem proces, spýtam sa: „Je to niečo, čo ma baví robiť?" Ak áno, nechám to ľudské. Ak je to repetitívne, administratívne alebo čisto analytické, automatizujem to. Výsledok je, že svoj čas trávim na architektúre, vzťahoch s klientmi a drone inžinierstve — na veciach, ktoré skutočne vyžadujú ľudský úsudok.
